## 修复清单

### 1) P2-1：悬浮窗 CSP 漏 http，钉会话（pinSession）静默失效
- 现状：`debug/float.html:5` 的 `connect-src` 只放 `ws://127.0.0.1:*`，但
  `pinSession`（float.html:991-1003）用 `fetch('http://127.0.0.1:...')`。CSP 直接
  拦掉这个 fetch，点「钉会话」没有任何反应，也不报错。
- 改动：`connect-src` 追加 `http://127.0.0.1:*`（与 detail.html 一致）。
- 回滚：删掉该 token。

### 2) P1-a：Electron 运行时版本未固定、过旧版本照跑
- 改动：新增最低主版本 `MIN_ELECTRON_MAJOR = 43`（42 已于 2026-10-20 EOL）。
  - `index.js:811 electronRuntimeMajor(candidate)` 读运行时目录 `version` 文件；
  - `index.js:828 electronBinaryStatus()` 在自动发现路径上校验版本（
    `DSH_WASHER_ELECTRON` 显式覆盖则跳过，交给用户负责）；返回
    `reason: 'ok'|'platform'|'missing'|'old'`；
  - `launchOverlay`（index.js:1185）与 `/capabilities`（overlayReason）区分
    「没装」与「版本过旧」，设置页能给出准确文案；
  - `electron/start.sh:37` 同步加同一套守卫（自动发现 + 有 version 文件才算，
    读不出主版本号则放行）。
- 已验证：本机 `~/.dsh/electron/version`=`43.3.0` → 放行；伪造 `42.0.0` → 退出码 1
  且中文提示正常（变量用 `${VAR}` 括起，避免 C locale 下紧跟全角标点被吞）。
- 回滚：还原 `index.js` 的 `electronBinary()` 原实现 + 删除 `start.sh` 版本块。

### 3) P2-2：WebSocket 快照 ≥64KB 被静默丢弃
- 现状：`encodeWsText`（index.js:631）对 `length >= 65536` 直接 `return null`，
  `pushNow` 遇 null 就 return——超大会话的快照永远推不出去，浮窗冻在最后一帧，无报错。
- 改动：补 RFC 6455 的 127 + 8 字节扩展长度分支（`writeBigUInt64BE`），编码层
  能正确表达任意大小（index.js:645-651）。
- 回滚：改回 `return null`。

### 4) P2-3：Electron 窗口安全基线缺失
- 改动（`electron/main.cjs`）：
  - 悬浮窗/详情窗均加 `will-navigate`（只放行 `file://`）与
    `will-attach-webview` 拦截（main.cjs:569/573、932/935）；
  - 启动时 `session.defaultSession.setPermissionRequestHandler(...false)` +
    `setPermissionCheckHandler(() => false)`，默认拒绝一切 Web 权限（main.cjs:1102）。
  - 保留悬浮窗原有「外链走系统浏览器」的 `setWindowOpenHandler`，不覆盖其行为。
- 回滚：删除上述监听。

### 5) P2-4：127.0.0.1 服务缺 Host / Origin 校验
- 改动（index.js）：`hostHeaderAllowed`（673）/ `originHeaderAllowed`（680）/
  `localRequestAllowed`（689）；HTTP 派发器（1831）与 WS `onUpgrade`（1691）均在
  鉴权前校验。规则：Host 必须是 127.0.0.1 / localhost / [::1]；Origin 存在时必须
  是本机来源（`null` / `file://` / 本机 host 放行），缺失则交给 token 兜。
  防 DNS rebinding 与恶意网页借浏览器戳本机端口。
- 回滚：删除 `localRequestAllowed(req)` 两处调用即可（helper 留着无副作用）。

### 6) P1-c（最小版）：宿主私有 hook 契约集中
- 现状：`WasherDock` 里散着 10 处 `useChat(s => s.legacy.*)` / useProjection /
  useTrajectory 取法，宿主改字段名就全局静默失灵。
- 改动：抽成 `src/client.template.js:424 useDockSignals(props)`，`legacy.*` 逐个
  存在性兜底（拿不到退 undefined，不再抛 TypeError 白屏），`WasherDock`（738）
  统一从它取。未新建独立文件，避免动 build.mjs。
- 回滚：还原 `WasherDock` 顶部的取数块。

### 7) P1-b：client.js / render 测试不在 CI 门口
- 改动：
  - `package.json` `test` 追加 `test/freshness.test.mjs`，并在原生 `--test` 之后
    `&& node test/render.mjs --no-shots`（render.mjs 有自己的 harness 且会
    `process.exit`，不能进 `--test` 列表，只能作为独立进程串在末尾）；
  - `test/build.test.mjs` 新增 2 条哨兵：`client.js` 能被 `vm.Script` 解析、
    `__ModuleLoader__.load` 契约（id == 包名、带 factory）。
- 回滚：还原 test 脚本与删除新增用例。

### 8) P2-5：构建产物新鲜度无校验
- 改动：新增 `test/freshness.test.mjs`：在临时目录用 `src/` 重跑两个 build 脚本，
  产物必须与仓库内 `client.js` / `debug/float.machines.js` 逐字节一致，否则红。
  专治「改了 src/ 忘了 npm run build」——本地测试全绿、市场拿到的却是旧产物。
- 回滚：删除该测试文件并从 test 脚本移除。

### 9) engines 补 node
- `package.json` `engines` 增 `"node": ">=24"`（DSH 运行时 Node 24.21.0，本机 24.15.0）。
