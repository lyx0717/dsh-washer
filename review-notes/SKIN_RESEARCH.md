## 1. 现状：一个皮肤要落到几处

皮肤不是「换套配色」，是**同一造型的 React 版 + vanilla 版双实现**，外加尺寸与构建链。

| # | 触点 | 位置 | 说明 |
|---|---|---|---|
| 1 | React 渲染函数 | `src/client.template.js:292` `defineSkin()` / `:691-701` 两个内置皮肤 | 主界面 dock 停靠条用 |
| 2 | 注册尺寸 `NATURAL` | `src/client.template.js:308-312` | 只有 `pixel`/`precision` 两个 getter；新皮肤必须加 getter，否则 `BigMachine` 回退 pixel |
| 3 | 皮肤 CSS | `src/skin-precision.css`（precision） | 新皮肤要新建 CSS 文件 |
| 4 | 主构建 CSS 注入 | `build.mjs` 的 `__CSS__`（style.css + skin-precision.css） | 新 CSS 要挂进来 |
| 5 | 浮窗构建 | `build-float.mjs:105` `MACHINE_SVG`、`:141` `skinCss()`、`:252` `host.innerHTML = MACHINE_SVG`、`:325` `build()` 分发 | **只认 `precision`/`pixel` 两条分支**；新皮肤不加分支会静默画成像素机 |
| 6 | 窗口尺寸 | `electron/main.cjs:42` `PRECISION_ASPECT = 425/330`、`:56-59` `normalSize()` | 窗口高按「机身宽 × 425/330 + 留白 + 气泡道」算死；换宽高比必须加按皮肤的 aspect 表 |
| 7 | 浮窗宽高比 | `debug/float.html:1023,1270` 两处写死 `425/330` | 同上，新皮肤要同步改 |
| 8 | 设置页皮肤选择器 | `src/client.template.js:1091` `seg(...)` | 目前只有 `precision` 一个选项 |
| 9 | 测试 | `test/build.test.mjs:84` 遍历 `['pixel','precision']`；`test/render.mjs` 有皮肤相关断言 | 新皮肤要加进列表，否则不测 |

**结论**：新增一个皮肤 ≈ 改 8-9 处，其中第 1、5 是「写两遍渲染」——这是主要成本项，和画风无关。

## 2. 尺寸矩阵与「能不能看清」

### 2.1 现有尺寸

| 档位 | 窗口 | 机身显示宽 | 相对 330 设计宽的缩放 |
|---|---|---|---|
| 停靠条（dock） | — | **32px** | **0.097** |
| 浮窗 极简 | 76×96 | 64px | 0.194 |
| 浮窗 紧凑 | 106×205 | 86px | 0.261 |
| 浮窗 标准 | 132×238 | 112px | 0.339 |
| 浮窗 大 | 158×272 | 138px | 0.418 |
| 设计基准 | — | 330px（precision NATURAL） | 1.0 |

浮窗高度公式：`height = round((width-20) × 425/330 + 20 + 74)`，`74` 是气泡道（BUBBLE_LANE）。

### 2.2 量化结论（这决定皮肤能怎么画）

- **32px dock**：1 个设计像素 = 0.097 屏幕像素。少于约 **10 个设计像素**的特征，在 dock 上不到 1px，等于不存在。→ dock 只能靠**轮廓 + 1 个亮色点**辨识。
- **标准浮窗 112px**：1 设计像素 = 0.339px。≥3px 的细节才可见；文字要靠「粗、方、大」而不是字号。
- **黑条 LED 字号现状（是个硬问题）**：面板里 `state-text` 15px、`cnt` 13px、`timer` 13px（`src/skin-precision.css:195-205`），随机身缩放后，标准档只有 **≈5.1px / 4.4px / 4.4px**——基本不可读。这不是本次新增，是现存状态，必须和皮肤一起解决：要么把面板字号做成「不随机身缩放」（浮窗用真实 px 覆盖层），要么把信息降级成大字/符号。
- 结论：**新皮肤必须在两个极端都成立**——32px 的 dock 图标、112-158px 的浮窗。细节越多，32px 越糊。

## 3. 皮肤的三种可交付形态（成本差很大）

| 形态 | 做法 | 成本 | 适合 |
|---|---|---|---|
| **A. SVG 资产型**（像素皮肤就是这套，`src/machine.svg` 13.4KB，viewBox 64×78，单文件 `innerHTML` 注入，动画靠外层 CSS 变量 `--water/--foam/--led/--spin`） | 画一张 SVG + CSS，两套渲染都变成「注入同一份 SVG」 | **最低** | 轮廓清晰、少细节的风格（纸艺、复古、工业线稿） |
| **B. 手写 DOM 型**（precision 这套：`build-float` 逐节点 `el()/text()`） | React + vanilla 各写一份同构 DOM | 最高（≈2 倍） | 需要精细缩放/分层动画/玻璃质感的「主角皮肤」 |
| **C. 混合** | 主体用 SVG，关键件（滚筒/灯/黑条）用 DOM 覆盖 | 中 | 需要「动」的部位多，但外形简单 |

**对本次的意义**：如果接受「新皮肤用 SVG 资产型」，每个皮肤的成本从「两套渲染」降到「一张 SVG + 一段 CSS + 注册」，8-9 处触点变成机械性小改；如果每个皮肤都要手写 DOM，3 个皮肤就是 6 份实现。

## 4. 设计空间：6 个风格族（按 32px 可辨识度排）

> 只描述风格语汇，不指名特定品牌的产品参数。

| 族 | 视觉语汇 | 32px 辨识锚 | 动画语言 | 与「洗衣机 + 安静」调性 | 风险 |
|---|---|---|---|---|---|
| **复古奶油** | 奶油白机身、木纹/米色顶盖、机械旋钮、暖琥珀灯 | 奶油圆角块 + 琥珀点 | 旋钮慢转、暖光呼吸 | 高（有生活感、不吵） | 木纹画不好会显脏 |
| **纸艺手绘** | 纸白、墨蓝线稿、少量橙、纸纹 | 白块 + 手绘圆门 + 橙点 | 线条轻微抖动、便签气泡 | 高（最"生活化俏皮"，正好接你上次说的通知语气） | 线稿在 32px 要足够粗 |
| **工业不锈钢** | 拉丝银灰、深灰蓝、螺栓、黄黑警示、绿点阵屏 | 银块 + 黑窗 + 绿点 | 硬朗步进、警示闪 | 中（硬、有存在感） | 32px 银色容易糊成灰块 |
| **太空舱 HUD** | 深底 + 青色发光环 + 扫描线 | 深胶囊 + 青环 | 扫描、脉冲 | 中低（和"安静"冲突，且偏冷） | 发光细线在 32px 全糊；深底易撞你账本里的"深·近黑" |
| **透明亚克力/玻璃拟态** | 半透明机身、内部结构若隐若现 | 几乎无锚点 | 折射高光 | 低 | 32px 不可辨 |
| **像素 8bit**（现有，已下架） | 硬边像素、有限色 | 强 | 方格跳动 | 中 | 已有资产，复活成本最低 |

## 6. 关键技术待确认（不是画风问题，是工程问题）

1. **窗口宽高比**：`main.cjs` 与 `float.html` 都写死 `425/330`。新皮肤若比例不同（比如方块机 1:1），窗口公式要改成按皮肤取 aspect；否则机器会在窗口里被拉伸/留大白边。
2. **暗色主题**：`build-float.mjs` 的 `skinCss()` 只抽 `.dsh-washer` 亮色变量段（`[data-ds-dark-theme]` 覆盖没进去）。新皮肤的 CSS 必须自带亮/暗两套，或明确"不跟随系统"。
3. **黑条可读性**（§2.2）：标准和紧凑档只有约 5px 字。要么浮窗把黑条做成不缩放的覆盖层，要么把字做成粗块。这个必须先定，否则新皮肤做完还是看不清。
4. **测试**：`test/build.test.mjs:84` 的皮肤列表、`test/render.mjs` 的断言要逐个补；新增皮肤必须过 10 态渲染。
