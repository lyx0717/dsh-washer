# 《DeepSeek 洗衣机桌宠插件 · 扩展功能规划》评估（针对 dsh-washer 现状）

> 评估基准：dsh-washer v0.7.4 现状。该插件不是泛用「桌面宠物」，是 DeepSeek Harness(DSH) 的**状态显示器**：数据源只有宿主事件（turn / tool / usage / outline / trajectory），定位是「不用盯屏也知道 Agent 跑到哪了，只在洗完/卡住/等你确认三个时刻叫人，其余安静」。判断「合理且优雅」的标准因此有两条硬约束：**①每个动作必须对应一个可验证的宿主信号**（浮窗源码里写死的原则）；**②不破坏「安静、极简」的原生形态**（S/M/L 卡片、ETA 都是当年刻意删掉的）。

## 结论先行
- **值得做、且能优雅落地**：①任务缩略预览（= 扩展现有详情面板，顺带把上轮 deferred 的「洗衣记录」一起做掉）、③菜单加「打开 Harness 客户端 / 暂停监听」、④负载强度可视化（前提是只用可解释信号算 loadFactor）、四.1 智能贴边收纳（tiny + 悬停展开）、四.3 透明度调节。
- **已有 / 别重复做**：②任务通知提醒（完成/故障/等你确认/卡住 + 音效 + 勿扰 + 前台静音 + 节流，上轮刚做完）、四.5 深浅主题（已跟随宿主）、贴边吸附（已有 24pt snap）、多会话概览（已有圆点 3+N + 可点切换）、详情面板（已有本轮耗时/token/工具耗时/缓存命中率）。
- **不建议**：⑤多台洗衣机自由摆放（与本插件「单浮窗 + 圆点概览」取舍冲突，更吵更抢屏）、⑥今日/本周指标仪表盘（要持久化遥测，是另一个产品）、④里的「排队脏衣堆叠」（插件没有「排队」这个宿主信号，凭空）、四.4 气泡避让鼠标（浮窗本身极小，无意义）。
- **低价值/选做**：⑦标签过滤、⑧状态回放（开发者调试向）、三.彩蛋（打盹类纯视觉可做，成就/皮肤包成本高）。

## 逐项评估

### 一、轻量实用功能

| 项 | 判断 | 理由 & 优雅落点 | 优先级 |
|---|---|---|---|
| ① 任务缩略预览面板 | ✅ 值得做 | 不要新建「第二个浮窗」——**扩展现有 `debug/detail.html` 详情面板**即可：加「最近 N 轮」列表（正是 deferred 的洗衣记录）+ 报错一键复制 + 点条目 pin/跳转。入口沿用右键「查看详情」。避免两套面板并存。 | P1（中） |
| ② 任务通知提醒 | ⚠️ 基本已实现 | 完成/故障/等你确认/卡住 + 音效 + 勿扰 + 前台静音 + 节流都已具备。唯一新增点是「**自动**免打扰」（检测 IDE 全屏/前台时自动静音）——但 DSH 插件拿不到 IDE 全屏信号，最多用「窗口是否前台」，增益有限。 | P2（低） |
| ③ 快速菜单扩容 | ✅ 部分合理 | 现有菜单已有：查看详情/极简/造型/穿透/重连刷新/退出。「打开 Harness 客户端」「暂停监听（休眠）」合理且小改（暂停=host 侧 paused 开关，别卸载）；「清空历史」依赖①的历史；「打开日志目录」需先确认有落盘日志。 | P1（中） |
| ④ 负载强度可视化 | ⚠️ 亮点但有风险 | 方向和插件「量化状态」气质契合，但**必须用可解释信号**：token 速率(speed)、同时 running 工具数、当前 step 工具数 → 归一成 0..1 loadFactor 去驱动 VISUAL 的 spin/foam 幅度，否则就是「编造动画」，违背核心原则。「排队脏衣堆叠」插件无队列概念，不建议。 | P1（中，需克制） |

### 二、进阶功能

| 项 | 判断 | 理由 | 优先级 |
|---|---|---|---|
| ⑤ 多任务集群（多台洗衣机自由摆放） | ❌ 不推荐 | 与本插件取舍正面冲突：已用「单个桌面浮窗跟随 pinned 会话 + 多会话圆点(3+N，可点切换)」来表达多会话，就是为**避免多窗干扰**。多台自由摆放会很吵、抢屏幕、和「安静」定位相悖。 | — |
| ⑥ 简易指标仪表盘（今日/本周） | ❌ 不推荐（重） | 需要跨会话、跨重启的持久化遥测，等于在桌宠里塞一个 DevOps 看板，偏离定位。**轻量替代**：详情面板里加「本会话统计」（= deferred 功能8 累计用量），内存里就有，不做持久化。 | — |
| ⑦ 标签与过滤规则 | ⚠️ 可选 | 黑名单关键词/白名单目录若要，落点在 **host 折叠/推送层过滤 + 设置页简单文本输入**，别做进浮窗。对「只想安静」的用户有一点价值，但增加配置复杂度。 | P2（低） |
| ⑧ 状态快照与历史回放 | ⚠️ 仅开发用 | 用户价值低、开发量中偏大；若做，标 dev-only，不进正式产品形态。 | P3（低） |

### 三、趣味彩蛋

- **空闲抖动 / 打盹 / 空闲微动**：✅ 安全，纯视觉、零数据依赖，注意尊重 `reduced-motion`。低优先级。
- **连续失败提醒 / 成就贴纸**：⚠️ 需要持久统计（同⑥），成本高；「零报错一天」这类要跨重启记账。低/选做。
- **皮肤包**：⚠️ 等于多套 `defineSkin`，可行但有维护/体积成本；现有 pixel/precision 两套已是折中。低。

### 四、体验细节

| 项 | 判断 | 说明 |
|---|---|---|
| 1 智能贴边收纳（缩成图标悬停展开） | ✅ 合理 | 已有 24pt `snapToEdges` 吸附 + `tiny` 档。「悬停展开」优雅做法 = **tiny + hover 展开**，不新造一个「收纳态」状态机。注意 click-through 时收不到 hover，需非穿透才有意义。 |
| 2 帧率自适应（10/30fps） | ✅ 合理低中 | 与「不抢推理算力」契合，可做；但要实测功耗，别过度工程。 |
| 3 透明度调节 | ✅ 合理 | 设置页加滑杆 + 主进程 `setOpacity`，改动小。 |
| 4 气泡避让鼠标 | ❌ 不必 | 浮窗窗口本身极小，气泡贴底 8px，避让没有实际收益。 |
| 5 配色主题深/浅 | ✅ 已实现 | 已跟随宿主明暗（`setThemeDark` / `dark` 偏好），无需再做。 |

## 一个前提提醒
该文档明显是按「泛桌面宠物 / IDE 场景」写的（点击弹窗、IDE 全屏、排队脏衣、多台摆放、进程监控）。DSH 的真实数据源是**宿主事件流**，不包含 IDE 全屏、任务队列、系统进程这类信号。凡是依赖这些「拿不到的信号」的功能（自动免打扰、排队脏衣、⑥报表），要么降级成用现有信号近似，要么明确不做——**别假设能拿到**。

## 建议落地顺序（若要继续）
1. **① 任务预览**：扩 detail 面板「最近 N 轮 + 报错复制 + 点跳会话」，顺带消化 deferred 洗衣记录。
2. **③ 菜单**：「打开 Harness 客户端」+「暂停监听」。
3. **四.1 贴边收纳**（tiny + hover）+ **四.3 透明度**。
4. **④ 负载强度**（用 loadFactor，克制地驱动 VISUAL）。
5. 其余低优先级/可选。

开关原则（文档§六）与插件完全一致：**极简为原生形态，新增功能一律可选、默认关**——这点插件已经在做（hideWhenIdle / dnd / reduced-motion），继续保持即可。
